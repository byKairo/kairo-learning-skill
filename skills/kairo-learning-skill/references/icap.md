# ICAP：设计学习参与方式

ICAP 用于检查活动如何促进理解，不代替路线、检索练习、间隔复习和掌握检验，也不是每课依次走完的四步流程。

## 判断依据

| 模式 | 可观察行为 |
| --- | --- |
| P · Passive，被动接收 | 阅读、听讲，尚无可观察的加工产出 |
| A · Active，主动操作 | 划重点、摘抄、删句式摘要，主要操作已有信息 |
| C · Constructive，建构 | 产出材料没有直接给出的解释、推论、关系或例子 |
| I · Interactive，交互建构 | 双方承接彼此推理，提出实质贡献，共同修正或发展解释 |

依据是实际回答及其与材料的关系，不是任务名称。压缩字数或换同义词不能自动算 C；聊天次数、点击交互工具或用户表示赞同不能自动算 I。没有外显产出也不能断言用户没思考。分类存在不确定性时保留不确定。

来源：[Chi 与 Wylie，2014，原始论文](https://education.asu.edu/sites/default/files/lcl/chiwylie2014icap_2.pdf)，尤其定义与 Table 1。这里的 Chi 指 Michelene T. H. Chi；[一丹奖官方中文介绍](https://yidanprize.org/zh-cn/laureates/michelene-chi)对应中文名为季清华教授。论文提出有条件的 I > C > A > P 学习效果假说，不是每个个体、任务都成立的排名，也不是掌握等级。

## 在本 Skill 中的实现

以下是教学设计选择，不声称这套 AI 教学流程已被该论文验证。

- 系统学习中，围绕本轮目标选择一个有用的产出。用户已有作品就直接利用，不另加形式作业；知识不足先补最小讲解或样例，不为了追求 C/I 让新手盲猜。
- 要求压缩文本时说明目的。若目标是理解，可请用户简述核心观点，并补一个原文未提供的“为什么”、例子或适用边界；不强制字数和固定格式。若只需要摘要，直接满足。
- 收到回答后，先检查内容正确性，再看新增推理。机械摘抄时选一个关系请用户解释；已有合理推理时，可提出与其观点相关的反例或条件变化，等待用户回应。
- 推进交互时，承接用户具体论点，说明自己的理由或证据，让用户有机会修订或有依据地保留判断；随后结合双方贡献更新解释。不能只连续出题、评分，也不能代替用户完成双方讨论。
- 用户只说“懂了”或复述我的结论时，保留理解未验证；出现新增但错误的推理时按误区反馈，不能因为有建构行为就判为学会。
- 探索模式不强制出题。用户主动举例、反驳或提出推断时自然承接；只要解释时直接解释。用户跳过练习时继续原任务。
- 档案按原规则记录实际表现、提示程度和修正，不增设 ICAP 总分或强制标签。是否独立、保持和迁移仍由对应任务证据判断。
